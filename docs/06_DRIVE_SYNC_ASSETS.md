# 06. Google Drive synchronization and asset processing

## 1. Source scope

Verified branding source folders:

- Logos: `https://drive.google.com/drive/folders/163aOb9k-O236cVFmTJm7SH3ljHCs73Ky`
- Brandbooks: `https://drive.google.com/drive/folders/1AdwD2o7PhAzn8VYSr8YljsAdYiG-t2Ol`

The two roots are separate on purpose. The logo source is organized by numbered brand/sub-brand folders; the brandbook source separates core Affidea, sub-brands, associated brands and supporting material. Archives and historical folders are excluded from the approved web library.

The previous generic root `16hA1bCXCEQxRtWbNWC6apAZDPH7fW8sE` is not used as the canonical branding source for the current desktop delivery.

Use Drive IDs as stable identity. Paths and filenames are mutable labels.

## 2. Authentication to Google

Preferred: Google Cloud service account with read-only access to the shared drive/folder. Add the service account as a member or share the required root/folders according to Affidea policy. Use least-privilege Drive scopes that still permit metadata and content reads. Store credentials only as encrypted Cloudflare secrets.

If the source is a Shared Drive, all list/get/change calls must use the appropriate shared-drive flags and corpus. Service accounts cannot own normal Drive storage; they read content shared with them.

## 3. Initial crawl

1. Acquire a distributed sync lock.
2. Read root metadata and verify expected ID.
3. Traverse every descendant folder with pagination.
4. Upsert folders/files by Drive ID.
5. Store name, parent ID, MIME, extension, size, checksum when supplied, created/modified time, capabilities, Drive/Shared Drive ID and revision/version indicator.
6. Classify the file from its first-level area, brand folder and format.
7. Link it to a brand candidate or mark `unclassified`.
8. Preserve existing approval status by Drive ID.
9. New files default to `pending`.
10. Reconcile missing files only after a complete successful traversal.
11. Update start page token/change cursor.
12. Release lock and record counts/errors.

## 4. Incremental sync

Use Google Drive Changes API as the source of incremental truth.

- Webhook: `changes.watch` notifies the Worker.
- Notification body/header does not replace a Changes API read.
- On notification, enqueue/persist a sync job and acknowledge quickly.
- Consume changes from the stored page token until a new start token is reached.
- Cron every 5 minutes provides recovery if notifications fail.
- A separate scheduled task renews watch channels before expiry. Google currently documents a maximum of one week for `changes` channels.
- Store channel ID, resource ID, token hash, expiration and status in D1.

## 5. State behavior

### New file

Create asset with `pending`. Generate safe metadata/preview where possible. Do not show to ordinary users.

### Existing approved file modified

Update metadata and revision, invalidate preview and ZIP cache, regenerate, retain `approved`, and create an audit event attributed to `system:drive-sync`.

### Rename or move

Update path/brand classification. If the move changes the detected brand, flag `needs_review = true` but retain approval as requested. Admin receives a warning.

### Deleted/trashed/unreachable source

Set `source_missing`, remove from ordinary search/download, retain metadata and audit history. Do not hard-delete automatically.

### Duplicate content

Do not deduplicate by filename. Store distinct Drive IDs. Show duplicate warning when checksums match or name/size/revision strongly indicate duplication. Admin selects canonical variants.

## 6. Classification rules

- Guidelines area: classify PDF/Docs/Markdown by folder and filename status markers such as `CANONICAL`, `WORKING`, `ARCHIVE`.
- Logos area: first brand folder determines candidate brand; nested folders describe colour/format variants.
- Web/App area: link from filename prefix when deterministic; otherwise pending/unclassified.
- Data Centres: parse only approved XLSX sources configured in Admin; do not ingest every spreadsheet found elsewhere.
- AI/EPS are downloadable source formats but not rendered directly.

Classification is a proposal, not approval.

## 7. Preview strategy

Priority:

1. SVG served as an image after safe headers.
2. PNG/JPG/JPEG/TIF web rendition.
3. Cached Drive thumbnail fetched server-side.
4. PDF first-page thumbnail generated by an approved background service or cached provider thumbnail.
5. Generic format icon.

Do not attempt to render Adobe Illustrator/EPS inside the browser. Prefer a related approved PNG/SVG variant.

## 8. Download behavior

Blob files use Drive `files.get` with `alt=media`, authorized server-side, and are streamed. Google Workspace files use `files.export` with an approved target MIME type; note Google's documented export-size limit. Verify download capability.

Implement HTTP Range forwarding where safe for PDFs and larger cached objects. Original files must not be modified.

## 9. ZIP packs

- Admin controls `include_in_pack` per approved asset.
- Pack manifest is deterministic and versioned.
- Existing approved Drive ZIP may be selected as canonical.
- Otherwise build in background and store privately in R2.
- Cache key includes brand ID plus sorted file Drive IDs and revisions.
- Invalidate when an included revision/status changes.
- Exclude raw working folders, archive/history, rejected files and enormous source trees by default.
- Never package the full 1.9 GB OncoLink working folder automatically.

## 10. Data Centres ingestion

Canonical workbook: `https://docs.google.com/spreadsheets/d/1Kz3b712Prx2XRaEXdgbH_3Wt_8C-ofNt/edit?gid=509335129#gid=509335129` (`Centralizator_Centre_si_MC.xlsx`).

The `General Infos` tab currently contains 82 numbered centre records. Two records have no clinic name in the source; they must remain visible as incomplete source rows rather than being dropped or silently named. Parse by header mapping, not column position alone. Preserve the raw approved workbook as the source and map normalized fields:

- centre name;
- region/city/county;
- address;
- contact/manager;
- phone;
- legal entity;
- source sheet/row;
- additional columns as JSON.

Validate duplicate centre numbers, missing names, multiple phone formats and renamed centres. Swapping the approved workbook triggers a full centre-table reconciliation.

## 11. Failure handling

- Every sync job is idempotent.
- Retry transient 429/5xx responses with exponential backoff and jitter.
- Stop and flag authorization/quota/schema errors.
- Never mark files missing after a partial/failed crawl.
- Persist per-file errors and continue where safe.
- Surface last successful sync independently of last attempted sync.
